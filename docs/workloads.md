# Workloads and test conditions

## Test files

Generated by `python tests/gen_test_files.py` (fixed random seed, so they are identical on every machine). Hashes are in `tests/hashes.txt`:

| File | Size (bytes) | SHA-256 |
|---|---|---|
| `test_1MB.bin` | 1,000,000 | `1de31112b855d408acd1ce1d550350d8d6c64f422cff145b89cd5bbaf0190682` |
| `test_10MB.bin` | 10,000,000 | `2643ca1aaac8bb101ff56b24bb1fec3a8fa4ed55136dbe1dc8310089556f6bd0` |

## Workloads

| ID | Name | Definition | Measured |
|---|---|---|---|
| A | File transfer | Send `test_1MB.bin` and `test_10MB.bin`; receiver returns the SHA-256 of what it got | Duration (connect → hash received), throughput (Mbit/s), SHA-256 match, retransmissions (UDP) |
| B | Request/response | 1,000 sequential 64-byte request → echo exchanges | Per-exchange RTT (mean, p50, p95, max), retransmissions (UDP) |
| C | Periodic messages | 64-byte messages, 100 per second for 30 s (3,000 messages), each carrying a sequence number and send timestamp | Delivery % and one-way delay (mean, p95) |

## Network conditions

| Name | Loss (UDP, per direction) | Delay (each direction) | How |
|---|---|---|---|
| `clean` | 0% | 0 ms | Direct to server on 127.0.0.1, no proxy |
| `loss5_delay50` | 5% | 50 ms (≈100 ms RTT) | `tests/proxy.py` |
| `delay50`, `loss1_delay50` | 0% / 1% | 50 ms | Optional extra conditions (`--conditions`) |

Impairment applies in **both directions**, like `tc netem` on the loopback interface. See `docs/environment.md` for why TCP gets delay but no loss.

## Measurement rules

- All timing uses `time.perf_counter()`.
- Each cell (protocol × workload × condition) is run 6 times. Run 0 is a warm-up (flagged `warmup=1` in the CSV) and excluded from graphs. Runs 1–5 are measured.
- Every run, including the warm-up and any failures, is recorded in `results/results.csv` (final) or `results/baseline_results.csv` (baseline).
